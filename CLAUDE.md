# CLAUDE.md: Deadroll

Deadroll is a fully on-chain tabletop RPG on Solana. Every dice roll is public. Every death leaves a mark.
Real Dungeon Masters run live sessions; characters, maps, combat, dice, deaths and even the sprite renderer live on-chain.

- Design docs: `docs/` (Russian). They are the source of truth for **game rules**.
- `docs/ARCHITECTURE.md` is the source of truth for **how the code is split**.
- This file is the source of truth for **how agents work** right now.
- `agents/TASKS.md` is the task board for parallel agents. `agents/CONTRACTS.md` holds the frozen interfaces.
- `agents/GROK_FOR_CLAUDE.md` explains how to delegate bounded tasks to the Grok CLI.

---

## 0. Deadline mode (demo video on 2026-10-12)

We build the **target architecture** (7 programs, shared crates, on-chain rasterizer, VRF, Session Keys, Core NFTs), but in **priority tiers**. Several agents work in parallel. A tier is started only when the tier above it has a plan and owners.

| Tier | What | Rule |
|---|---|---|
| **P0** | everything the demo video shows (section 8) | must work end to end on devnet |
| **P1** | polish the video benefits from | only after P0 is green locally |
| **P2** | the rest of the design | skeletons and `TODO(post-demo)` only |

**Fallbacks are allowed only through a seam**, never by deleting the target design:
| Target | Fallback if blocked for more than 1 hour | Seam |
|---|---|---|
| MagicBlock VRF | `SlotHashesRoll` seed | all dice through `deadroll_combat::rng::RollSource` |
| MagicBlock Session Keys | burner key stored in `Participation.actor` | one helper `auth::check_actor(...)` used by every game instruction |
| Metaplex Core NFT | PDA only, `nft: Option<Pubkey>` = None | `character::cpi::mint_nft` behind a feature flag `nft` |
| Worker for wallets | static cover image in `uri` | `GameConfig.uri_base` |

Use the fallback, write `// FALLBACK(<name>): reason` and report it in the PR. Do not burn hours fighting a dependency.

## 2. Stack

- **Anchor 1.0** (`avm install latest && avm use latest`), **Solana CLI 3.x** (Agave), Surfpool as local validator.
- Program tests: LiteSVM (Rust) for single-program tests; `anchor test` for `tests/` integration.
- TS: `@solana/kit` + Codama clients in `sdk/`.
- MagicBlock: `ephemeral-vrf-sdk` (VRF), `session-keys` (Session Keys). Metaplex: `mpl-core`.
- **Before using any external crate API, check the installed version and its docs** (`cargo tree`, docs.rs, the crate source in `~/.cargo/registry`). Do not guess APIs from memory. If a crate does not compile with Anchor 1.0, stop and report: the lead decides between pinning Anchor or using the fallback.

## 4. Parallel work rules (multiple agents)

1. **One agent = one lane = one git worktree = one branch.** Lanes and their folders are in `agents/TASKS.md`. Never edit outside your lane's folders.
2. **`crates/types` and `agents/CONTRACTS.md` are frozen** after task L0. Changing them needs a separate PR by the lead lane; other lanes ask in their PR description instead of editing.
3. **Program IDs** are fixed in `Anchor.toml` and `agents/CONTRACTS.md` at L0. Never regenerate keypairs for an existing program.
4. **CPI between programs** uses only the instruction signatures in `CONTRACTS.md`. If you need a new one, add a stub in your lane and write it in the PR.
5. Merge order: `types` → crates → `registry`, `render` → `character`, `map` → `session` → `items`, `city` → `sdk` → `app`. Rebase on `main` before opening a PR.
6. **Never two write-capable agents on the same files**, including Grok.
7. Short bounded tasks (sprites, presets, tests, UI components, scripts) go to Grok per `agents/GROK_FOR_CLAUDE.md` and the `delegate-to-grok` skill. Claude reviews every Grok diff before commit.

## 5. Hard rules

1. **Integers only** in `crates/combat` and `crates/render`. Basis points: `10_000` = 100% = x1.
2. **No negative values.** Debuffs divide (counterweights), never subtract (`docs/COMBAT_MATH.md`, section 3).
3. **Game moves never create accounts.** Accounts for a party are created at `open_session` / `join_session` (`docs/GAME_COMMISSIONS.md`).
4. **One instruction = one file**, each with tests (happy path + every rejection).
5. **All dice through `RollSource`.** One VRF value per action, many rolls derived as `hash(seed ‖ roll_index)`.
6. **Hit order is fixed**: `docs/COMBAT_MATH.md`, section 6. The website uses the same crate through WASM.
7. **Trust between programs**: sensitive instructions accept only a PDA signer of a game program listed in `GameConfig` (`docs/ARCHITECTURE.md`, 4.3). CPI depth max 2 from the user instruction.
8. **Every account has `version: u8`** first after the discriminator. Fixed-size data, no unbounded `Vec` in game state.
9. **Never commit keys** (`*.keypair.json`, `id.json`, `.env`, `target/deploy/*.json`). Never print private keys.
10. **Never mention secret lore** (hidden guilds, encrypted fragments and similar) in code, comments, commits, assets or UI. If a doc section looks like secret lore, skip it.
11. Do not edit `docs/` unless the task says so.

## 8. Demo video script (P0, end to end on devnet)

1. The site loads the **rasterizer WASM from the chain**, checks its hash and draws sprites from the on-chain `SpriteBook`.
2. Two players create characters (human warrior with piercing predisposition, forest elf mage with cold). Each character is a **Core NFT** with its PDA state.
3. Players start a **session key** once; no wallet popups during play.
4. The DM builds a map from a preset in the builder, validates and finalizes it, opens a party with a price, players pay into escrow and join.
5. Combat with wolves: initiative, moves, attacks, **VRF rolls**, dice cascade with hit breakdown, a resonance triggers.
6. A character dies and becomes a **tombstone** (sprite changes, NFT frozen).
7. The party kills the goblin chief: victory, XP, loot, DM gets the price from escrow.
8. Explorer: every roll and every transaction is public.

## 9. How to work

1. Take a task from `agents/TASKS.md`, write your name in it.
2. Read the zone `CLAUDE.md` and the doc sections the task links.
3. Plan in 5-10 lines (files, accounts, CPI, tests). For P0 tasks post the plan before coding.
4. Implement, test, fix until green. Delegate bounded subtasks to Grok when they are faster there.
5. Conventional Commits: `feat(session): attack instruction`. PR with `Closes #N`, fill the template, list fallbacks used.
